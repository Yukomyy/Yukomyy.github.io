01 / CONTEXT

Overview & Problem Statement

Project Overview

Operational managers often look at delivery speed while finance teams look at monthly freight bills—rarely in the same system. This project bridges those two perspectives by reconciling shipment dispatch milestones with carrier billing lines into a unified decision-support interface.

Problem Statement

Carrier invoices billed at the consolidated manifest level while warehouse logs tracked individual waybills, preventing straightforward joins to calculate true cost per delivered order.

02 / DESIGN GOALS

Objectives & Engineering Solution

Key Objectives

  • 01Allocate manifest-level freight charges proportionally across constituent waybills by chargeable weight.
  • 02Flag SLA breaches (promised delivery date vs. actual proof-of-delivery timestamp) alongside cost overruns.
  • 03Present actionable route-level performance tables without visual clutter.

Solution Summary

I created a SQL reconciliation view that allocates manifest costs by weight ratio, flags unmatched waybills in an exception table, and surfaces route-level SLA and unit-cost metrics in a fast tabular web interface.

04 / IMPLEMENTATION

Selected Code & Query Logic

Proportional cost allocation is handled in SQL using partitioned window sums so that the sum of allocated waybill costs equals the exact carrier manifest invoice total.

sql/views/vw_allocated_shipment_costs.sqlsql
CREATE OR REPLACE VIEW vw_allocated_shipment_costs AS
SELECT
    w.waybill_id,
    w.manifest_id,
    w.origin_hub,
    w.destination_zone,
    w.chargeable_weight_kg,
    m.total_manifest_cost_idr,
    ROUND(
        m.total_manifest_cost_idr * (
            w.chargeable_weight_kg
            / NULLIF(SUM(w.chargeable_weight_kg) OVER (PARTITION BY w.manifest_id), 0)
        ),
        2
    ) AS allocated_freight_cost_idr,
    (w.delivered_at <= w.promised_sla_at) AS is_on_time_sla
FROM waybill_dispatches w
INNER JOIN carrier_manifest_invoices m
    ON w.manifest_id = m.manifest_id;
05 / ENGINEERING TRADE-OFFS

Challenges & Architectural Decisions

Technical Challenge

Rounding discrepancies when splitting a manifest invoice across dozens of small parcels.

Engineering Decision

Retained full numeric precision in intermediate analytical views and applied rounding only at the presentation aggregation layer.

Trade-off Accepted

Ensures finance roll-ups reconcile 100% with general ledger invoice totals.
