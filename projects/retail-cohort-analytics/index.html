01 / CONTEXT

Overview & Problem Statement

Project Overview

Aggregate revenue dashboards often tell managers what happened last month, but fail to explain whether growth comes from acquiring new customers or retaining existing ones. This project decomposes raw e-commerce invoice logs into cohort retention tables, Recency-Frequency-Monetary (RFM) segments, and product basket metrics.

Problem Statement

Raw transactional exports contained cancelled invoices, missing customer identifiers, negative adjustments, and inconsistent SKU descriptions—making naive SQL `SUM(quantity * price)` queries inaccurate by over 12%.

02 / DESIGN GOALS

Objectives & Engineering Solution

Key Objectives

  • 01Establish a documented data cleaning pipeline that separates valid commercial orders from returns, credit notes, and non-merchandise fees.
  • 02Construct SQL CTE pipelines to measure Month-0 to Month-12 retention across acquisition cohorts.
  • 03Segment active customers using quantile-based RFM scoring to prioritize retention campaigns.

Solution Summary

I built a two-stage workflow: a Python/Pandas validation script that standardizes raw CSV invoice dumps and flags data anomalies, followed by an analytical SQL layer in PostgreSQL/DuckDB that materializes cohort retention views and RFM customer profiles consumed by the reporting dashboard.

04 / IMPLEMENTATION

Selected Code & Query Logic

Below is the core analytical SQL query that assigns each customer to their acquisition month cohort and computes active customer retention percentages across subsequent months.

sql/cohort_retention_matrix.sqlsql
WITH customer_first_purchase AS (
    SELECT
        customer_id,
        DATE_TRUNC('month', MIN(invoice_timestamp))::date AS cohort_month
    FROM fct_clean_orders
    WHERE is_cancelled = FALSE AND customer_id IS NOT NULL
    GROUP BY customer_id
),
monthly_activity AS (
    SELECT DISTINCT
        o.customer_id,
        c.cohort_month,
        DATE_TRUNC('month', o.invoice_timestamp)::date AS activity_month,
        (EXTRACT(YEAR FROM AGE(DATE_TRUNC('month', o.invoice_timestamp), c.cohort_month)) * 12
         + EXTRACT(MONTH FROM AGE(DATE_TRUNC('month', o.invoice_timestamp), c.cohort_month)))::int AS month_number
    FROM fct_clean_orders o
    INNER JOIN customer_first_purchase c ON o.customer_id = c.customer_id
    WHERE o.is_cancelled = FALSE
)
SELECT
    cohort_month,
    month_number,
    COUNT(DISTINCT customer_id) AS active_customers,
    ROUND(
        100.0 * COUNT(DISTINCT customer_id)
        / FIRST_VALUE(COUNT(DISTINCT customer_id)) OVER (
            PARTITION BY cohort_month ORDER BY month_number
        ),
        2
    ) AS retention_rate_pct
FROM monthly_activity
GROUP BY cohort_month, month_number
ORDER BY cohort_month, month_number;
05 / ENGINEERING TRADE-OFFS

Challenges & Architectural Decisions

Technical Challenge

Handling guest checkouts (null `customer_id`) without distorting overall revenue totals.

Engineering Decision

Split analytical marts into `fct_store_revenue` (includes guest orders) and `fct_customer_cohorts` (authenticated customers only).

Trade-off Accepted

Requires clear metric documentation on dashboards so stakeholders understand the denominator of each chart.

Results & What I Learned

Verifiable Outcomes

  • ✓Quantified the 12.4% discrepancy between gross invoiced sales and net realized revenue after isolating credit notes.
  • ✓Identified steepest retention drop-off between Month 0 and Month 1, highlighting the window for post-first-purchase onboarding.

What I Learned
